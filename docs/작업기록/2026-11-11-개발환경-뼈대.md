## 왜 이렇게 했나
- **uv + pyproject.toml**: `uv.lock`이 정확한 버전을 고정해서, 내 컴퓨터와 나중의 Docker 안에 똑같은 버전이 깔린다.
- **`backend/` 폴더로 분리**: 2주차에 `frontend/`(React)가 생겨도 파이썬과 자바스크립트가 섞이지 않는다.
- **처음부터 PostgreSQL**: 2주차의 벡터 검색(pgvector)은 SQLite로 안 되고, upsert나 중간값 계산도 DB마다 동작이 달라서 나중에 옮기면 일이 두 번이 된다.
- **Docker에는 db, redis만**: Django와 Celery는 코드를 자주 고치니 내 컴퓨터에서 `uv run`으로 돌리는 게 빠르다. web, celery, celery-beat, frontend 컨테이너는 2주차 7일에 추가한다.
- **비밀값은 `.env`에만**: `startproject`가 `settings.py`에 직접 적어 둔 `SECRET_KEY`를 커밋 전에 환경변수로 바꿨다.
- **DB 주소, Redis 주소는 기본값 `localhost`**: 나중에 컨테이너로 옮길 때 `.env`에 `POSTGRES_HOST=db`, `CELERY_BROKER_URL=redis://redis:6379/0`만 넣으면 된다.

## 막혔던 것과 배운 것
- `docker-compose.yml`의 `service:` → `services:`. 모르는 키는 compose가 바로 에러를 낸다.
- `POSTGER_DB`, `CELERY_BROKE_URL`처럼 **문자열 안의 오타는 에러가 안 난다.** 기본값으로 조용히 돌아가다가 나중에 터진다.
- `django.db.backend.postgresql` → `backends`. 긴 에러는 맨 아래 몇 줄에 답이 있다.
- `No module named 'packaging'`: `celery`와 `redis`를 따로 설치하면 Redis용 부품이 빠진다. `celery[redis]`로 설치해야 한다.
- 파이썬 파일 이름은 소문자로 쓴다 (`Celery.py` → `celery.py`). 리눅스는 대소문자를 구분한다.
- pgvector는 DB가 따로 있는 게 아니라 PostgreSQL에 얹는 확장 기능이다 (`CREATE EXTENSION vector`).

- `manage.py test`: 아직 테스트 0개 (3일차 모델부터 추가)

## 실행 방법 (지금 기준)
```bash
docker compose up -d                                              # db, redis 켜기
cd backend
uv run --env-file ../.env python manage.py migrate                # DB 테이블 만들기
uv run --env-file ../.env python manage.py runserver              # Django 실행
uv run --env-file ../.env celery -A config worker -l info         # Celery 작업자 실행 (다른 터미널)
```
